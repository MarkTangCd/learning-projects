Lesson 02 · backtrader 框架评估

Strategy 与 Indicator

把你自己的指标搬进框架,并证明它搬对了。 然后看着一行从不执行的死代码把 +28.7% 变成 −11.4%。

这节课的单一胜利 写一个 你自己的 Indicator(隔壁那个 Efficiency Ratio), 用两种写法实现,与 pandas 版逐位对拍——最大偏差 0.00e+00。 这证明了一件对使命至关重要的事:backtrader 不是黑箱,你的存量资产可以迁移且可验证。

一、Strategy 的五个钩子

你在 L1 只用了两个:__init__ 和 next()。完整的是五个, 其中两个你可能从没听说过——而它们正是今天那个 bug 的藏身处:

1
__init__
跑一次。只声明 line 对象,不计算。此时没有任何值。
2
start
跑一次。数据已挂载,第一根 bar 还没送来。
3
prenext
每根预热期的 bar 调一次。默认什么都不做。你的 next() 不会被调用。
4
nextstart
只调一次:预热刚好满足的那根 bar。默认实现 = 调 next()。
5
next
此后每根 bar 调一次。你的决策写在这。
6
stop
跑一次。收尾、存结果。
cd ~/learning-projects/backtrader-framework/practice
./venv/bin/python l02_strategy_indicator.py hooks
  __init__     声明完毕。self.sma 现在是个 line 对象,还没有值。minperiod=30
  start()      数据已挂载。策略 minperiod=30
  prenext()    bar#1  指标还没算够 —— next() 不会被调用
  prenext()    bar#29 指标还没算够 —— next() 不会被调用
  nextstart()  bar#30 date=2023-12-15  sma=39721.24  <- 第一根可用的 bar
  next()       bar#30 sma[0]=39721.24  sma[-1]=nan          <- 注意这个 nan
  stop()       跑完 60 根 bar,前 29 根被 prenext 吃掉了

minperiod:一个 line 需要多少根 bar 才能给出第一个值。 SMA(30) 的 minperiod 就是 30。框架自动推断它,自动跳过预热期—— 你手搓栈里那些 .iloc[window:] / dropna() 是你自己写的,这里白送。

这是真价值 自动 minperiod 消灭了一整类前视偏差:你不可能读到一个还没算够的指标值, 因为那根 bar 上你的 next() 压根不会被调用。 但注意 nextstart 那根 bar 上 sma[-1] 仍然是 nan—— 指标有值,不代表它的历史有值。任何 x[0] > x[-1] 式的比较在第一根上都会静默失效。

二、bug 时间:一行死代码

minperiod 会向上传染:策略的 minperiod = 所有已声明指标的最大值。 "已声明"——不是"已使用"。

def __init__(self):
    f = bt.ind.SMA(self.data.close, period=10)
    s = bt.ind.SMA(self.data.close, period=30)
    self.cross = bt.ind.CrossOver(f, s)
    self.unused = bt.ind.SMA(self.data.close, period=200)   # 声明了,从不读,不画图

self.unused 是纯死代码——注释掉它,买卖逻辑一个字符都不会变。跑跑看:

./venv/bin/python l02_strategy_indicator.py minperiod

声明了就要算,算了就要等。等的那段时间,回测还没开始—— SMA(200) 把起点从 2023-12 推到 2024-06,吃掉了 4 笔交易, 其中包含 2024 上半年那波行情。结论从"赚 28.7%"翻转成"亏 11.4%"。

为什么这条特别毒 它是间歇性的。SMA(50) 同样推迟了起点(晚 19 天),结果却一模一样—— 因为那段窗口里刚好没有信号。所以这个坑大部分时候不咬人, 你会误以为"多声明几个指标无所谓",直到某次它吃掉了一笔关键交易。 没有警告、没有报错、两次运行的输出格式完全相同。
这正是你在隔壁课程反复训练的那类 bug:不报错的错。

怎么防:任何跨策略/跨参数的对比,先固定一条共同起点—— 用 fromdate 明确切数据,或让所有对比组声明同一组指标。 别让"回测窗口"成为一个由 __init__ 里最长那个 period 隐式决定的量。

你把一个策略的 SMA(200) 趋势过滤器删掉了,只留 SMA(10)/SMA(30) 交叉。回测收益变了。最可能的原因是?
对。minperiod 是所有已声明指标的最大值,它决定回测的真实起点。起点变,样本变,结论变。
不是。买卖逻辑与费用都没动。变的是 minperiod —— 回测起点提前了,样本不同了。

三、写你自己的 Indicator

把隔壁 strategy.py 里的 Kaufman Efficiency Ratio 搬进来。 ER = |window 内净变动| / 走过的总路程,趋近 1 是单边趋势,趋近 0 是震荡。

写法 A:声明式(在 __init__ 里做 line 运算)

class EfficiencyRatio(bt.Indicator):
    lines = ("er",)                  # 输出线的名字
    params = dict(period=20)
    plotinfo = dict(subplot=True)    # 单独一格画,不叠在价格上

    def __init__(self):
        c = self.data
        net = abs(c - c(-self.p.period))                      # c(-n) = 整条线延迟 n 根
        total = bt.ind.SumN(abs(c - c(-1)), period=self.p.period)
        self.lines.er = net / total
        super().__init__()           # minperiod 由操作数自动推断

关键语法:c(-n)(圆括号)是整条线延迟 n 根, 而 c[-n](方括号)是当前 bar 往前第 n 个标量值。 __init__ 里只能用圆括号——那里还没有"当前 bar"。

写法 B:命令式(自己逐 bar 填线)

class EfficiencyRatioLoop(bt.Indicator):
    lines = ("er",)
    params = dict(period=20)

    def __init__(self):
        self.addminperiod(self.p.period + 1)     # 这种写法要【自己】声明预热期

    def next(self):
        n, c = self.p.period, self.data
        net = abs(c[0] - c[-n])
        total = sum(abs(c[-i] - c[-i - 1]) for i in range(n))
        self.lines.er[0] = net / total if total else 0.0
声明式 A命令式 B
minperiod自动推断你自己写,写错不报错
速度快(内部批量求值)慢(Python 逐 bar 循环)
能表达的逻辑受限于 line 运算符任意(状态机、条件分支)
适用纯数学变换带状态/带记忆的逻辑

三种实现逐位吻合。这是本节课真正的胜利: 你手搓栈里的任何指标都能搬进 backtrader,而且你有办法证明它搬对了。 迁移风险从"未知"降级成"可验证"。

对拍是本课程的标准动作 凡是要用框架替代你已有实现的地方,先跑一次对拍。 L1 那个夏普对上了(所以可信),今天这个 ER 也对上了。 L6 会把整条策略拿去对拍——那时对不上,你才知道该怀疑谁。

但请注意这张表本身的问题:我刚刚在 4 个阈值里挑,而你在看最右边那一列。 如果 0.3 那格恰好是 +150%,你会不会想"ER 闸门有效"? 这就是隔壁 L22 的选择方差——框架把扫参数变得太便宜, 而便宜的搜索会稳定地生产出好看的样本内数字。L7 会正面打这一仗。

省了

  • minperiod 自动推断:一整类"读到未算够的值"的前视偏差被结构性消灭
  • 预热期自动跳过,不用再写 dropna() / .iloc[w:]
  • 自定义 Indicator 是一等公民:lines + params 两行就能接入全部管线
  • 两种写法可选:纯数学用声明式(快),带状态用命令式(灵活)
  • 与 pandas 逐位对拍通过 —— 存量指标可迁移,且迁移正确性可证明

坑了

  • minperiod 传染:一行从不执行的死代码能把 +28.7% 变成 −11.4%,零警告
  • 而且间歇性发作——SMA(50) 同样推迟起点却结果不变,让人放松警惕
  • 回测窗口成了 __init__ 的隐式副产品,不是一个你显式设定的量
  • x(-n) 与 x[-n] 语义完全不同,写错通常不报错
  • 命令式 Indicator 的 addminperiod 要手写,写小了会读到脏数据
  • 参数扫描变得太便宜 —— 这是特性,也是过拟合的加速器
本课的评估结论(累计第 2 条) Indicator 层是 backtrader 目前为止最值得买的部分: 接口小、可自定义、可对拍,并且顺手消灭了一类前视偏差。 代价是它引入了一个你手搓栈里不存在的隐式状态——minperiod。
使用纪律:永远显式固定回测起点(fromdate), 别让指标的 period 决定你的样本。
