夏普比率

一个公式,四个决定。你以为你在读一个数字,其实你在读四个选择。

公式

Sharpe = mean(r - rf) / std(r) * sqrt(N)

  r    收益序列(每根 bar 一个数)
  rf   同周期的无风险利率
  std  收益的标准差
  N    一年有多少个 bar —— 年化因子

字面意思:每承担一单位波动,换来多少超额收益;乘 sqrt(N) 把它折算成"一年"的口径,好让日线和月线能互相比较。

为什么是 sqrt(N) 而不是 N:收益按 N 倍累加, 但独立同分布的波动只按 sqrt(N) 倍累加。分子涨 N,分母涨 √N,比值涨 √N。

四个决定(公式没告诉你的部分)

决定选项影响
① 用哪条收益序列 日 / 周 / 月 / 年;账户净值收益 vs 持仓收益 最大。同一策略,日线 n=1000 vs 年线 n=4,是两个完全不同的统计量
② 年化因子 N 股票 252,crypto 365,周线 52,月线 12 crypto 上误用 252 → 系统性虚低 sqrt(365/252)=1.2035 倍
③ 无风险利率 rf 0 / 当期国债 / 某个写死的常数 短样本、低收益时影响大;还要注意它减在年化前还是年化后
④ 标准差的自由度 ddof=0(总体)/ ddof=1(样本) n 大时可忽略;n=4 时差 15%。pandas 默认 ddof=1,numpy 默认 0
报数字时必须一起报的 「Sharpe 0.83」是一句不完整的话。完整版是: 「日收益、n=1912、rf=0、ddof=0、年化因子 252,Sharpe 0.83」。 两个人报的 Sharpe 对不上,九成是这四项里有一项不一样,而不是策略不一样。

手算(用你自己 L1 的数字)

import pandas as pd, numpy as np

r = pd.Series(strat.analyzers.ret.get_analysis())   # TimeReturn(timeframe=Days)
sharpe = r.mean() / r.std(ddof=0) * np.sqrt(365)    # crypto -> 365
mean(r)std(r)nNSharpe
BTC0.0003740.01567810003650.4559
SPY0.0003670.00702719122520.8281

注意 BTC 和 SPY 的日均收益几乎一样(0.000374 vs 0.000367)。 Sharpe 差近一倍,全部来自分母——BTC 的日波动是 SPY 的 2.2 倍。 这就是 Sharpe 在说的唯一一件事:同样的钱,你付了多少颠簸。

backtrader 的默认值,拆开看

源码:backtrader/analyzers/sharpe.py。默认参数:

timeframe    = TimeFrame.Years   # 用【年度】收益序列,不是日收益
riskfreerate = 0.01              # 写死 1%
convertrate  = True              # 把年利率折算到 timeframe(Years -> 因子 1,不变)
annualize    = False             # 不再乘 sqrt(N)
stddev_sample= False             # ddof=0
factor       = None              # 走内置表 {Days:252, Weeks:52, Months:12, Years:1}

所以 bt.analyzers.SharpeRatio 不加参数时,算的是:

mean(年度收益 - 0.01) / std_总体(年度收益)

用 BTC 那份 1000 根日线实测复现(TimeReturn(timeframe=Years) 导出年度收益):

这个默认值的问题 n = 4,其中两个是残年(2023 只有 1.5 个月,2026 只到 8 月)。 用 4 个样本(含 2 个不可比样本)算标准差,统计上没有意义。 而它不报错、不警告、返回一个长得很像 Sharpe 的数。
更早的实测里数据更短、折不出 ≥2 个年度收益时,它静默返回 None—— 同一个 API,失败模式随数据长度改变。

让它诚实的写法

cerebro.addanalyzer(
    bt.analyzers.SharpeRatio,
    timeframe=bt.TimeFrame.Days,   # ① 用日收益
    compression=1,
    annualize=True,                # 乘 sqrt(factor)
    factor=365,                    # ② crypto 用 365;股票 252。【必须显式写】
    riskfreerate=0.0,              # ③ 明确 rf
)                                  # ④ stddev_sample 默认 False = ddof=0
factor 为什么必须显式写 annualize=True 而不给 factor 时,它查内置表 {Days: 252}。 这个 252 是硬编码的,对 7×24 的 crypto 系统性虚低 1.2035 倍,而且不会提示你。

比数值本身更该看的:它有多不确定

Sharpe 是从有限样本估出来的,自带误差棒。Lo (2002) 的近似(同周期口径):

SE(Sharpe) ≈ sqrt((1 + Sharpe² / 2) / n)     # n = 样本数,不是年数
年化时误差棒同样乘 sqrt(N)
年化 Sharpe± 1 SEt = SR/SE读法
BTC0.4560.6040.75与 0 无法区分
SPY0.8290.3632.28勉强显著(且这是样本内)

换句话说:L1 里那个 BTC 的 0.4559,算得完全正确,但它什么也没证明。 把小数点后四位当结论用,是比用错 252 更贵的错误。

Sharpe 不说的事

  • 不分好坏波动:暴涨和暴跌一样罚。(想只罚下跌 → Sortino)
  • 看不见回撤路径:两个策略 Sharpe 相同,一个最大回撤 10% 一个 50%。(→ Calmar)
  • 假设收益独立:自相关(动量/趋势策略常有)会让 Sharpe 虚高。
  • 对肥尾无感:卖期权式的"天天赚一点、偶尔爆掉"能刷出很高的 Sharpe。
  • 不做多重检验校正:扫 100 组参数取最好的那个 Sharpe,期望值天然大于 0。
