# 挑战③判决：10 笔历史交易全部有止损与目标——问题不在"无计划"，在执行与盈亏比

用户（2026-10-12）回忆填入最近 10 笔 BTC 永续交易，**10/10 能写出进场 / 止损 / 目标 / 出场价**（未记数量、手续费、时间）。这推翻了 L1 的工作假设"盈亏随机 = 无计划交易占多数"：用户有计划，计划没被执行到底。

## Evidence（`journal.py stats`，手续费按 0 计，真实净值更低）
- 期望值 **−0.38R/笔**，总计 −3.8R；胜率 30%；平均盈利 +0.77R，平均亏损 −0.88R
- 计划 R 平均 **1.25R**（0.86–1.97）→ 打平需胜率 ≥ 44%，实际 30%
- 执行分布：**到目标 0 笔**；提前止盈 3（平均 +0.77R，计划约 1.2R）；提前小亏平仓 3（−0.56R）；到止损 2；**超出止损 2**（−1.21R，滑点或挪止损）
- 止损距离 0.4%–2.4%（40–240 bp），是多小时持仓的量级，不是剥头皮
- Setup 名称已有词汇：pullback、trading range reversal、channel reversal、breakout（Al Brooks 式术语）→ 用户看过价格行为材料
- 顺带：用户数据暴露了 `journal.py` 的 bug——原版把"没填 qty"判成无计划；已改为按价格比计算 R，qty / 手续费可选

## Implications
- L3（风险规则）要直接针对两件事：**超出止损**（交易所挂真实止损单而非心理止损）与**0 笔到目标**（出场规则，而不是更多进场规则）
- 盈亏比 1.25R 过低是结构问题：要么目标放远（需要时段有足够区间，L2 的内容），要么止损收窄（需要进场更精确，L4–L6）
- 不必再向用户解释"什么是 setup"，但 setup 的触发条件尚未写成可检验的规则（L7 PlayBook）
- 待确认：这 10 个止损是当时真写下的，还是现在回忆重建的（影响"计划存在"结论的强度）
