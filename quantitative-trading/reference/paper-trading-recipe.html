纸上交易 tick 配方

一根 K 线一次决策的实盘心跳。向量化回测的"活"版本。配 L8。

tick 四步

# ① Poll:拉最新 K 线,丢掉未收盘的最后一根
df = fetch_ohlcv(timeframe="1d", limit=SLOW + 40).iloc[:-1]
price = float(df["close"].iloc[-1])

# ② Signal:在已收盘数据上算目标仓位(= shift(1) 的实盘形态)
fast = df["close"].rolling(FAST).mean().iloc[-1]
slow = df["close"].rolling(SLOW).mean().iloc[-1]
desired = int(fast > slow)

# ③ Compare + 幂等:只在"严格更新的K线"且"目标≠当前"时下单
#   用 <= 比时间序,不用 == :既挡重复 tick,也挡"时间倒退"(切周期/陈旧feed)
last = pd.Timestamp(state["last_ts"]) if state["last_ts"] else None
if last is not None and bar_ts <= last:  return state   # 无更新K线 -> 不动作
if desired != state["position"]:
    # ④ Act:模拟成交 + 扣费,更新虚拟账户
    if desired == 1:
        state["coin"] = state["cash"] * (1 - FEE) / price; state["cash"] = 0.0
    else:
        state["cash"] = state["coin"] * price * (1 - FEE); state["coin"] = 0.0
    state["position"] = desired
state["last_ts"] = bar_ts
equity = state["cash"] + state["coin"] * price          # mark-to-market

三条实盘纪律

纪律怎么落实不做会怎样
① 只对已收盘 K 线动作df.iloc[:-1] 丢掉 forming candle用未定数据决策 = 前视偏差实盘版
② 状态持久化持仓/现金存 JSON,每 tick 读写重启丢仓位,账户对不上
③ 幂等下单目标=当前仓位就不动作同一根 K 线重复下单
④ 闸门比时间序,非相等bar_ts <= last_ts → 不动作时间倒退时"对着过去下单"
⑤ 账本按周期命名空间paper_state_{sym}_{tf}.json切 --tf 串味 → 拿 4h 状态比 1d K线,误成交

状态最小结构

{ "cash": 10000.0, "coin": 0.0, "position": 0,
  "entry": 0.0, "last_ts": "2026-08-05 ...", "trades": [] }
这仍是模拟(要心里有数) 按现价即时且必然成交、无部分成交、无延迟、无断线。真正的实盘要处理订单生命周期(下单/部分成交/撤单/超时/对账)与风控/急停——那是执行深水区。paper trading 的价值:在接真钱前,把时区/断网/状态错乱这些回测看不见的 bug 全暴露出来。工业级实现见 freqtrade dry-run。
