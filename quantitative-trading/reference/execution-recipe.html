真实执行配方

把订单发到真交易所并对账的最小骨架。替换掉纸上交易的"即时必成交"假设。配 L9。

三步纪律:SEND → READ BACK → RECONCILE

# 0) 建测试网客户端(set_sandbox_mode 必须在任何请求前调用)
ex = ccxt.binance({"apiKey": KEY, "secret": SECRET, "enableRateLimit": True})
ex.httpsProxy = "http://127.0.0.1:1087"
ex.set_sandbox_mode(True)          # -> testnet.binance.vision;key 也须是测试网 key
ex.load_markets()

# 1) SEND —— 过风控闸门后才发;clientOrderId = 幂等钥匙(意图的纯函数,非时钟!见 L10)
ok, why = pre_trade_check(ex, side, amount, price)   # 见下方
if not ok: return
cid = f"{SYMBOL}-{side}-{bar_ts}"                     # 同意图->同钥匙,重试不下重单
o = ex.create_order(SYMBOL, "market", "buy", amount, None,
                    {"clientOrderId": cid})

# 2) READ BACK —— 别信下单回执,回读订单簿里的真相
filled = ex.fetch_order(o["id"], SYMBOL)

# 3) RECONCILE —— 我以为的 vs 实际发生的
slip_bps = (filled["average"] - assumed) / assumed * 1e4
# 记账均价用 filled["average"];手续费不在订单头!在成交明细里:
fee = sum(t["fee"]["cost"] for t in ex.fetch_order_trades(o["id"], SYMBOL))
# 注:测试网盘口是合成的,滑点常为 0 —— 真实成本要到实盘才测得出

统一订单结构:下单后必读字段

字段含义下单方法
id / clientOrderId交易所 id / 你给的幂等 idcreate_order(sym, type, side, amount, price, params)
statusopen / closed / canceledfetch_order(id, sym)
filled / remaining已成 / 未成数量fetch_open_orders(sym)
average实际成交均价(算滑点用它)cancel_order(id, sym)
cost / fee成交额 / 真实手续费(Binance 的 fee 在成交明细里,订单头常为 None→ fetch_order_trades)fetch_balance()

订单生命周期(状态机)

SEND ──▶ open ──▶ closed        # 全额成交(终态)
          │  └──▶ partial ──▶ …  # 部分成交,剩余继续挂
          ├──▶ canceled          # 你撤单 / 超时(终态)
          └──▶ rejected          # 余额/精度/风控被拒(终态)

限价 vs 市价

类型保证放弃角色/费率
limit 限价价格 ≤ 你的价可能不成交(一直挂)maker,费率低
market 市价立即成交价格不定(吃穿盘口=滑点)taker,费率高

风控闸门(每张单前置,可拒单)

def pre_trade_check(ex, side, amount, price):
    if os.path.exists(KILL_FILE):                 # ① 急停:最先、最便宜
        return False, "KILL SWITCH ON"
    notional = amount * price
    if notional > MAX_NOTIONAL_USDT:              # ② 名义上限:挡 fat-finger
        return False, "over notional cap"
    min_cost = ex.market(SYMBOL)["limits"]["cost"]["min"]
    if min_cost and notional < min_cost:          # ③ 最小下单额
        return False, "below exchange minimum"
    return True, "ok"

幂等重试:断网后不下重单(L10)

# 幂等钥匙 = 交易意图的纯函数,重试时不变(绝不含 time.time())
cid = f"{SYMBOL}-{side}-{bar_ts}"
try:
    o = ex.create_order(SYMBOL, "limit", side, amount, price,
                        {"clientOrderId": cid})
except ccxt.RequestTimeout:                      # 不知道成没成 -> 先查,别盲发
    existing = ex.fetch_order(cid, SYMBOL)        # 用 clientOrderId 回读
    o = existing or ex.create_order(SYMBOL, "limit", side, amount, price,
                                    {"clientOrderId": cid})  # 同 cid 兜底
# Binance 对重复 cid 抛 ccxt.DuplicateOrderId -> 交易所已替你去重
这仍不是全部(执行深水区还在更深处) 生产级执行还要处理:部分成交后追单/撤单(下一课候选)、对账循环(定期用 fetch_balance / fetch_open_orders 校准本地账本 vs 交易所真相)、限频(enableRateLimit)。超时与幂等见 L10。工业级实现见 freqtrade / NautilusTrader。术语见 词表。
