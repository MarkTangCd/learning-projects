向量化回测配方

一份 position 列 → 一条诚实的收益曲线。无循环,纯列运算。配 L4。

前提

一张带时间索引的 df,含 close 列,和一列 position(0/1,已 shift(1) 防前视偏差)。

四步配方

FEE = 0.001   # 单边成本:手续费 + 滑点粗估

# ① 资产每根收益
df["ret"] = df["close"].pct_change()

# ② 策略收益:只在持仓时吃到涨跌
df["strat_ret"] = df["position"] * df["ret"]

# ③ 扣成本:position 变化 = 一次换手
df["trade"] = df["position"].diff().abs()
df["strat_ret_net"] = df["strat_ret"] - df["trade"] * FEE

# ④ 复利成曲线(起点 1.0)+ 基准
df["equity_net"]  = (1 + df["strat_ret_net"].fillna(0)).cumprod()
df["equity_hold"] = (1 + df["ret"].fillna(0)).cumprod()   # 买入持有

读数

total_net  = df["equity_net"].iloc[-1]  - 1     # 策略含成本总收益
total_hold = df["equity_hold"].iloc[-1] - 1     # 及格线
trades     = int(df["trade"].sum())             # 总成交笔数

三条诚实纪律

纪律怎么落实
① 不用未来信息position = signal.shift(1);丢掉未收盘 K 线。延迟由收益区间的起点决定,不是常数——见下
② 扣掉交易成本trade × FEE,含手续费 + 滑点
③ 和"躺平"比永远对比 equity_hold(买入持有)

成交假设:收盘成交 vs 次日开盘(L24)

shift(1) + 收盘价收益 = "收盘算信号,按那个收盘价成交"。crypto 永不收市,成立;股票在信号存在时已收市,最早只能次日开盘。

# 诚实的股票成交:两处一起改,少改一处就是新的前视 bug
df["ret"]      = df["open"].pct_change()   # open[t-1] -> open[t]
df["position"] = df["signal"].shift(2)     # 不是 1
成交假设收益列延迟为什么
收盘成交(crypto)close.pct_change()shift(1)区间起点是 close[t−1],决策用 close[t−1]
次日开盘(股票)open.pct_change()shift(2)区间起点是 open[t−1],决策只能用 close[t−2]
这个改动值多少钱?一条实测过的公式

年化损失 ≈ 换手/年 × 每笔跳空成本,其中每笔跳空成本 = 换仓方向 × (open[t+1]/close[t] − 1)。在 5 标的 × 4 策略 = 20 个格子上验证,误差几乎都 <0.2%。

换手是唯一的放大器。 低换手策略(4 次/年)几乎不受影响——哪怕隔夜段承载了总收益的 92%:那个数字关于持有,跳空只在换仓那天作用于你。

但符号是随机的。 20 格里变差 10、变好 10,面板均值 +0.03%/年,单格 −2.2% ~ +4.3%。跳空是无偏噪声,不改变期望、只放大方差。所以改它不是为了省成本,是为了让你的夏普里不再掺着分不清的运气。换手越高,掺得越多。

这个配方的简化假设(要心里有数) 成本固定、无部分成交/无资金约束、无爆仓/保证金、成交价就是 OHLC 里的某一个(没有盘口深度)。够用来快速筛选策略,但实盘前需用 freqtrade / vectorbt 等引擎做更真实的验证。完整的"回测 vs 实盘"差距清单见 QuantConnect Reality Modeling。
