第 3 课 · 工位 02 信号

你的第一个信号

把一张价格表,变成一列"买 / 卖 / 持有"的决策。数据 → 决策,流水线的第二段。

L2 你拿到了干净的 K 线。今天挂在 L1 的工位 ②「信号」:写一段逻辑,把价格映射成仓位决策。看得见的胜利——你会得到一列 position:1 = 持有,0 = 空仓。

今天不算盈亏(那是 L4 回测的事)。今天只做一件事,而且要做对:把信号算出来,并且不作弊(不使用未来信息)。这一点才是全课的重点。

先懂一个东西:移动均线 SMA

移动均线(Simple Moving Average, SMA)= 最近 N 根收盘价的平均值。它把上蹿下跳的价格抹平,让你看清趋势方向。没有可怕的数学:

SMA(10) 在今天 = (最近 10 根收盘价之和) ÷ 10
  • 快线(窗口小,如 10):贴着价格跑,反应快。
  • 慢线(窗口大,如 30):迟钝,代表大趋势。

信号逻辑:均线交叉

一个经典、朴素的趋势策略——快线在慢线之上就持有,否则空仓:

快线 > 慢线
position = 1
短期动能向上,趋势偏多 → 持有。
快线 ≤ 慢线
position = 0
动能转弱 → 空仓离场。

(先只做多头/空仓两种状态,暂不做做空——把概念跑通优先。)

代码:三步算出信号

# 假设 df 已是 L2 那张带时间索引的表,含 "close" 列

# 1) 两条均线
df["sma_fast"] = df["close"].rolling(10).mean()
df["sma_slow"] = df["close"].rolling(30).mean()

# 2) 原始信号:快线在慢线之上 → 想持有(1),否则空仓(0)
df["signal"] = (df["sma_fast"] > df["sma_slow"]).astype(int)

# 3) 关键一步:把信号后移一根,才是"能真正执行"的仓位
df["position"] = df["signal"].shift(1)

为什么第 3 步是全课的灵魂

不 shift 就是作弊 第 2 步的 signal 用了今天的收盘价算出来。但今天的收盘价,要等这根 K 线收盘那一刻你才知道——你不可能在知道收盘价的"同一根 K 线"里就按它建好仓。若直接拿 signal 当仓位,等于假设你能"用今天的结果做今天的交易",这就是 前视偏差(look-ahead bias)——回测暴赚、实盘暴死的头号元凶。

shift(1) 把每个决策顺延到下一根 K 线:根据已收盘的这根算出信号,到下一根才建仓。这才是现实中能执行的时序。记住这条铁律:

信号用已收盘的数据算 → 仓位在下一根才生效。

这也正好呼应 L2 的"丢掉未收盘的最新一根":信号环节的一切,都建立在"只用已经确定的过去"之上。

看一眼成果

print(df[["close","sma_fast","sma_slow","signal","position"]].tail(10))

# 数一数:一共给出了多少次"进场"(从空仓变持有)?
entries = ((df["position"] == 1) & (df["position"].shift(1) == 0)).sum()
print("进场次数:", entries)

前 30 行的 sma_slow 会是 NaN(数据不够 30 根算不出均线),对应的 position 也会是 NaN——这是正常且正确的:那段时间你的策略"还没准备好",本就不该有仓位。

呼应 L1 架构戒律 你现在写的这段"信号"代码,将来回测和实盘要共用同一份(L1:一份信号,两处运行)。所以从今天起就把它写干净、写成可复用的函数——下一课我们就拿它去回测。

随手一测

算出 signal 后必须 shift(1) 再当仓位,根本原因是?
对。signal 用了本根收盘价,而你只有等它收盘才知道;不 shift 就等于用未来信息建仓 = 前视偏差。shift(1) 把仓位顺延到下一根,还原真实时序。
关键在时序:signal 用了本根收盘价,而你要等收盘才知道它。不 shift 就用了未来信息(前视偏差)。shift(1) 让仓位在下一根才生效。
前 29 行的 position 是 NaN(算不出 30 周期慢线),正确的态度是?
对。均线需要足够历史才算得出,预热期内策略"未就绪",没有仓位是正确的。硬填数值反而会制造虚假交易。
这是均线的"预热期":历史不够就是算不出,那段没有仓位是对的。硬填数值会制造本不存在的虚假交易。
