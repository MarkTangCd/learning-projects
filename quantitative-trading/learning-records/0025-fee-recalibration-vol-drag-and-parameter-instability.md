# 0025 — 用实测费率重估 L16:三个发现,一个比一个重要

- **日期**: 2026-08-11
- **触发**: L20/L21 实测手续费 4 bp/边,而 `backtest.py:13` 的 `FEE=0.001`(10 bp/边)是 L4 拍脑袋填的
- **方法**: 冻结机器(GGRID/folds/walk-forward 全不动),只改「一笔交易的价格」,扫费率看**衰减形状**
- **判据在看数之前定好**(见下"预注册")

## 预注册的判据

| 结果 | 预定解读 |
|---|---|
| 夏普大幅转好 | edge 之前被过度惩罚,但对成本极敏感 = **脆弱** |
| 夏普微升 | edge 本来就薄,成本不是主要矛盾 |
| 夏普仍 ≤ 0 | 成本假设无关,问题在信号 |

**触发第一行**(BTC 双边 Sharpe 0.12 → 0.26)。但真正的收获在后面两条。

## 发现 1:夏普 +0.26,CAGR −0.06% —— 波动率拖累吃光一切

BTC 双边组合在实测 4 bp 下:

```
算术均值 +0.0367%/日 -> 年化 +13.39%
几何均值 -0.0002%/日 -> 年化  -0.06%
年化波动 52.1%   ->  拖累 σ²/2 = 13.57%
```

**+13.39% 的算术 edge 被 13.57% 的波动率拖累精确抹平。** 夏普量的是**算术**,
CAGR 量的是**几何**——所以夏普好看而你一分不赚。这是 L15"读全三列"的第二次兑现。

**CAGR 的盈亏平衡费率 = 4 bp,正好落在实测手续费上**;而滑点那一半仍未测量
(测试网合成盘口量不出)→ **真实成本 > 4 bp → 真实 CAGR < 0**。

### 修法来自 L18,且效果是可预测的

拖累 = σ²/2,是 σ 的**二次**函数 → 压 σ 收益是超线性的。加 vol 定量(4 bp, max_lev 3):

| 方案 | Sharpe | CAGR | MaxDD | 年化波动 | 拖累 σ²/2 |
|---|---|---|---|---|---|
| 不定量 | 0.26 | −0.1% | −35.2% | 52.1% | 13.6% |
| vol 目标 30% | 0.41 | +8.5% | −21.3% | 33.7% | 5.7% |
| vol 目标 20% | 0.41 | +7.0% | −14.4% | 22.5% | 2.5% |
| vol 目标 15% | 0.41 | +5.7% | −10.9% | 16.9% | 1.4% |

**三档 Sharpe 完全相同(0.41)** = L18"vol 目标是风险旋钮不改 edge"第二次确证。
CAGR 从 −0.1% 变 +7.0%,**信号一个字没改**——全部来自削掉拖累。
意外:vol 定量**降低**换手(93.9 → 41.0 次/年),因为缩小的仓位翻转时变动也小。

## 发现 2(最重要):参数不稳定性把费率效应甩开一个数量级

`vol目标20%` 的 walk-forward 曲线 0bp→1.04、4bp→0.41,**陡得离谱**,成本算不出这个幅度。
**钉死参数**再扫费率,曲线立刻变平缓:

```
参数(20, 0.35)   0bp:+1.13  4bp:+1.03  10bp:+0.90  20bp:+0.67   <- 平缓,符合成本数学
参数(30, 0.35)   0bp:-0.72  4bp:-0.78  10bp:-0.88  20bp:-1.05
```

陡降的真因:**某个 fold 的选参在跳**(fold 2 从 (10,0.35) 跳到 (30,0.25))。

9 组参数的样本外 Sharpe 散布(vol20%, 4bp):

```
er_window=10:  +0.84  +1.71  +1.38     <- 全正
er_window=20:  +0.44  +1.03  +0.29     <- 全正但弱
er_window=30:  -0.52  -0.78  -0.21     <- 全负
最好 +1.71 / 最差 -0.78 / 标准差 0.81
```

**对比两个"参数"的影响力:**

| 变量 | 摆动幅度 |
|---|---|
| 费率填错 6 bp(10→4) | Sharpe 移动 **0.14** |
| 网格上挪一格(er_window 20→30) | Sharpe 移动 **1.85** |

**我花两课测出来的成本参数,重要性不到选参的十分之一。** 这不是说测成本没用
(它是**确定性**支出,噪声会均值回零而它不会),而是:**优先级排错了**。
L13 起累积的"参数漂移黄灯"(4/7 → 5/7)一直是真警报,只是从没被量化成夏普单位。

## 发现 3:等权平均打赢挑最好

不做选择、9 组参数**等权平均**:

```
                     0bp     4bp    10bp    20bp
walk-forward 挑最好   1.04    0.41    0.27   -0.09
全网格等权平均         0.73    0.61    0.45   +0.17
```

4 bp 下 **0.61 > 0.41**,且对费率**明显更耐受**(20bp 仍为正)。
原因:walk-forward 的**样本内**挑选在 2/7 个 fold 里挑中了最差的参数族(er_window=30)。
等权平均不做选择 → 没有选择方差可言。代价是把好的和坏的一起平均。

**但注意一个红旗**:`er_window` 上 Sharpe 是**单调**的(10 > 20 > 30),而 **10 是网格下边界**
—— 最优可能在网格**之外**。"最优落在网格边缘"= 网格划错了,这是独立于以上所有结论的问题。
